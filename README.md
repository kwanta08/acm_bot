# 鳥人間サークル 統合運営 Discord Bot

[![CI](https://github.com/kwanta08/acm_bot/actions/workflows/ci.yml/badge.svg)](https://github.com/kwanta08/acm_bot/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

**日程調整・タスク・班/メンバー・桁巻き積層記録・機体進捗を、Discord の中だけで回す**
鳥人間サークル（人力飛行機・鳥人間コンテスト系）向けの運営 Bot です。

導入するサークルがやることは **招待URLを踏んで `/setup` を実行するだけ**。
VPS も Bot トークンも `.env` の編集も要りません。

```
/schedule create   ミーティングの日程を決める（リアクションで出欠投票 → 自動締切）
/task add          やることを配って追いかける（Todoist と同期）
/layer start       桁巻きの積層を記録する（作業時間は自動計算）
/progress view     機体 → パーツ → 部品 の進捗をツリーで見る
```

---

## 何をする Bot か

サークル運営でバラバラになりがちな作業を、Discord 1か所へ集めます。

| これまで | この Bot では |
|---|---|
| 日程調整のたびに外部サービスへ誘導し、回答を手集計 | チャンネルに投票が立ち、締切で自動集計。未回答者には催促 DM |
| 桁巻きの作業を紙の日誌やスプレッドシートへ手入力 | `/layer start` → `/layer end` の2コマンド。作業時間は自動計算 |
| Todoist は埋まっているのに機体全体で何%か分からない | 積層記録と Todoist を機体の進捗ツリーへ自動集計 |
| 代替わりのたびに設定を作り直す | `/season rollover` で卒業者の仕分け・班長リセット・年度スナップショット |

### 鳥人間サークルに絞っている理由

桁巻き・積層・主桁・機体といったドメイン用語を、**そのままコマンドとして扱います**。
他大学の鳥人間サークルにも同じ言葉が通じるので、汎用語へ言い換えるとかえって
何の機能か分からなくなるためです。

一方で**サークルごとに違うもの**——サークル名・班構成・機体名・桁の構成・
チャンネル・ロール——は一切ハードコードしていません。初期値も持たず、
すべて Discord 上から設定します。他大学のデータが混ざることもありません
（全データがサーバー単位で分離されています）。

「どんなサークルでも使える汎用運営 bot」ではありません。

## 3ステップで始める

対象: 導入するサークルの Discord サーバー管理者（`サーバー管理` 権限を持つ人）。所要 15 分ほど。

### 1. 招待する

運営者から受け取った招待URLを開き、自分のサークルのサーバーを選びます。

> **招待URL**: 公開準備中です。公開後にここへ掲載します。
> 自分の Bot として試したい場合は [セットアップ手順書](club-bot/docs/SETUP.md) を参照してください
> （起動ログに最小権限の招待URLが出力されます）。

要求する権限は最小限で、`Administrator` は要求しません。

| 権限 | 用途 |
|---|---|
| チャンネルを見る / メッセージを送信 | コマンドへの応答・各種通知 |
| 埋め込みリンク / ファイルを添付 | 一覧表示・CSV の送信 |
| リアクションを追加 / メッセージ履歴を読む | 日程調整の出欠投票 |

招待した瞬間に、導入手順の案内が1つのチャンネルへ投稿されます。

### 2. `/setup` を実行する

設定ウィザードが開きます。通知チャンネル・ロール・サークル名を選び、
班名をカンマ区切りで入力すると、班と対応する Discord ロールがまとめて作られます。

**班にも桁名にも初期値はありません。** あなたのサークルの構成をそのまま登録してください。

### 3. 使い始める

冒頭のコマンドから。**[取扱説明書](club-bot/docs/GUIDE.md) に、役割別の
「最初に覚えること」から年度替わりの引き継ぎまでまとめてあります。**

## 機能

### 鳥人間サークル向け

| 機能 | できること |
|---|---|
| **桁巻き積層記録**（`/layer`） | 誰が・どの桁の・何層目を・何分やったかを記録。`start` → `end` の2コマンドで作業時間は自動計算。桁名はサークルごとに登録 |
| **機体進捗管理**（`/progress`） | 機体 → パーツ → 部品 の木構造をドリルダウン表示。子の進捗から親を再帰的に集計。積層記録と Todoist から自動反映 |
| **重量管理**（`/weight`） | 目標重量と実測重量をツリーで積み上げ、超過の大きい順に表示。人力機は重量が成績に直結します |
| **大会からの逆算**（`/milestone` `/countdown`） | 大会日と節目の期限から必要ペースを逆算。遅れがある週だけ月曜に通知 |

### 運営全般

| 機能 | できること |
|---|---|
| 日程調整（`/schedule`） | リアクション投票・自動締切・未回答者への催促 DM・確定日の告知と前日/当日リマインド |
| タスク管理（`/task` `/today`） | 期限付きタスク・班別通知・「今日やること」ラベル。正本は Todoist |
| 班・メンバー管理（`/team-*` `/member`） | 班の作成とロール紐付け・班をまたいだ支援候補の検索・新入生オンボーディング |
| 資材の在庫（`/stock`） | 消耗品の増減記録と、発注閾値を割ったときの朝の通知 |
| 年度替わり（`/season`） | 卒業者の仕分け・班長フラグの一括リセット・年度スナップショット。卒業者の記録は消しません |
| レポート（`/report` `/me`） | 週次サマリー・出欠率・タスク CSV 出力・操作ログ |
| データの持ち出しと削除（`/data`） | 主要14テーブルを ZIP（CSV 群）で export。`delete` で自分のサーバーのデータを自分で削除（取り消し可） |

### Web ダッシュボード（任意）

Discord でログインして、自分のサーバーのデータを**表形式で閲覧・編集**できる Web UI です。
運営者が Bot とは別プロセスで公開します。CSV でのダウンロードにも対応。
**表示・編集は自分のサーバーのデータだけ**に限定されます。

## プライバシー

- **メッセージの本文を読み取りません。** `MESSAGE CONTENT` 特権インテントを要求しない設計で、
  再混入は回帰テストで検出しています
- 全データ・設定・権限・通知が**サーバー（`guild_id`）単位で完全に分離**されています。
  コマンドは実行されたサーバーにスコープされ、DM からの実行は拒否します
- Todoist のトークンは各サーバーの管理者がフォームから登録し、暗号化して保存します。
  **Bot の運用者にトークンを渡す必要はありません**
- **やめるときの連絡は不要です。** Bot をキックすれば動作が止まり、30日後に自動削除
  （その間に再招待すればデータは戻ります）。すぐ消すなら `/data delete`

収集項目の全一覧は [プライバシーポリシー](club-bot/docs/PRIVACY.md) を参照してください。

## リポジトリの構成

```
acm_bot/
├── README.md              このファイル
├── CONTRIBUTING.md        開発の始め方（環境構築・テスト・PR）
├── AGENTS.md              開発規約（絶対に守るルール）
├── docker-compose.yml     Bot 単体を Docker で起動する構成
└── club-bot/              ← コード本体
    ├── bot.py             エントリポイント・Cog の読み込み・自動ジョブ
    ├── cogs/              機能ごとのコマンド群（19 Cog）
    ├── services/          外部連携（Todoist・日程調整・積層記録）
    ├── repositories/      DB アクセス（全メソッドが guild_id を必須で受け取る）
    ├── utils/             DB 接続・権限判定・設定解決
    ├── dashboard/         Web ダッシュボード（bot とは別プロセスの FastAPI アプリ）
    ├── migrations/        スキーマ migration
    ├── deploy/            systemd ユニット・Caddyfile・Docker Compose 構成
    ├── tests/             pytest（CI で SQLite と PostgreSQL の両方を回します）
    └── docs/              ドキュメント一式
```

技術的な詳細（マルチテナントの実装方針・インテント・進捗集計のしくみ）は
[club-bot/README.md](club-bot/README.md) にあります。
