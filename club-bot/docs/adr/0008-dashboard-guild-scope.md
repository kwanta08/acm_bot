# 0008: ダッシュボードにおける `guild_id` スコープの強制層

## 文脈

Web ダッシュボードは複数の大学サークル（テナント）が同一インスタンスを共有する。
本プロジェクトが最も避けるべき事故は **「他大学のデータが見えること」** である。

リポジトリ層はすでに `guild_id` を必須引数にしているため、Web 層が守るべきは実質的に一点に
集約される — **セッションで検証済みの `guild_id` 以外を、絶対にリポジトリへ渡さないこと。**

Bot と違い Web 層では、対象サーバー ID が URL パスという**利用者が自由に書き換えられる場所**から
来る。ここが Bot 側（`interaction.guild_id` を Discord が保証する）との決定的な差である。

## 選択肢

| | 内容 |
|---|---|
| **A** | ハンドラが `guild_id: int` を Path パラメータで受け取り、各ルート冒頭でセッションと照合して 403 |
| **B** | ハンドラが生の `guild_id` を受け取れないようにし、検証済みスコープ型のみを渡す |

## 決定

**B を採用する。間違った `guild_id` を渡すことを「検査する」のではなく、「型として表現できなくする」。**

1. ルートハンドラは `guild_id: int` を**直接受け取らない**。
   受け取れるのは `ScopedGuild` / `EditorGuild` / `AdminGuild` の Annotated 依存性のみ
2. `GuildScope` は `require_guild_scope()` のみが生成する。URL・リクエストボディ由来の値からは
   構築できない。**このオブジェクトを保持していること自体が「検証済み」の証明**になる
3. リポジトリへは `scope.bind(repo)` 経由でしか触れない
   （＝検証済み `guild_id` を注入した `for_guild` プロキシを返す）
4. 権限は `GuildScope.require(level)` で、L4＝サーバー管理権限 / L2＝班長 / L1＝参加者の3段階。
   ロール ID による L3（幹部）判定は Bot トークン無しでは不可能なため扱わない
5. 403 のメッセージにサーバー名等を含めない（存在の有無を推測させない）

結果として、誤った `guild_id` をリポジトリへ渡すには
**意図的に `dashboard/security.py` を迂回するコードを書く必要がある。**

## 却下した案 (A)

1. **オプトイン方式であり、書き忘れが「動くが漏れる」形の障害になる。**
   検査を1行落としたルートは、正常系のテストでは完全に動作する。壊れないので気付けない
2. **レビューで検知しづらい。** 欠落しているコードは、存在するコードより目に入らない
3. **正しさがルート数に比例して再検証を要する。** エンドポイントを追加するたびに、
   システム全体の安全性がその新しいルート1本の書き手の注意力に依存する

避けたい事故の深刻度（テナント間のデータ漏洩＝サービスの信頼が即座に失われる）に対して、
「毎回きちんと書く」に依存する設計は釣り合わない。

## 迂回していないことの検証

`tests/test_dashboard_scope.py` が実行時テストと静的検査の両方を行う:

- A大学の利用者が B大学の URL を叩くと 403 になり、本文に B大学の情報が出ない
- 件数が必ず自サーバー分だけになる（B大学は件数を変えて配置し、混入を検出する）
- **AST・型注釈でハンドラが生の `guild_id` を受け取っていないことを静的検査**

3点目が本 ADR の要である。決定を文書だけでなく CI で強制する。

## 同じ思想の前例

`ProgressRepository.update_node`（P1-2）では、`guild_id` / `node_id` を位置引数と同名にして
**キーワードで渡せなくし**、テナント越境の更新を構造的に防いでいる。

本プロジェクトの一貫した方針として:
**テナント境界は「検査する」のではなく「表現できなくする」。**

## 影響範囲

- ルートを新規追加するとき、書き手は安全のための作業を何もしなくてよい。
  依存性の型を書く以外に `guild_id` を得る手段が無いため、安全な形が唯一の書き方になる
- 生の `guild_id` が必要な処理（管理用スクリプト等）は、この層の外に置く
- `scope.bind()` が使う `for_guild` プロキシは [0009](./0009-services-guild-id-freeze-lifted.md) で
  撤去対象とされているが、**本用途は恒久的**である。撤去時は置き換え先を先に用意すること

## 覆す条件

Bot トークンをダッシュボードが保持する構成に変わった場合、L3（ロール ID による幹部判定）が
可能になるため、権限レベルの3段階制は再検討する。スコープ強制の仕組み自体は影響を受けない。
