CHAPTER 0 — FOR EVERYONE

Discord の基本

まずここだけ読んでください。ここが分かれば、あとは自分の段の章だけで足ります。

0-1　この Bot は「コマンド」で動かします

Discord のいちばん下にある入力欄に /（半角のスラッシュ）を打つと、 使えるコマンドの一覧が出てきます。そこから選んで Enter を押すだけです。 覚えて打ち込む必要はありません。一覧から選べます。

図0-2　スラッシュコマンドの3ステップ。打ち間違いが起きないよう、ほとんどの入力は一覧から選べます。
どのコマンドがあるか分からなくなったら /help と打つと、カテゴリから探せます。 自分が使えないコマンドには鍵マークが付くので、 「これは自分には無理なやつだ」とすぐ分かります。

0-2　Bot の返事は「自分にだけ見える」ことが多い

コマンドの返事の多くは、打った本人にしか見えません。 チャンネルが Bot の返事で埋まらないようにするためです。 「あなたにのみ表示されています」と小さく書いてあれば、それは自分専用の表示です。 他の人には見えていないので、共有したいときは自分でコピーして貼ってください。

図0-3　返事の見え方は2種類。ほとんどのコマンドは右（自分だけ）です。

0-3　出欠は「ボタンを押す」だけ。コマンドは要りません

日程調整の投票は、コマンドを打つ必要がありません。 投稿されたメッセージの下にある絵文字を押すだけです。候補日ごとに1つのメッセージが投稿されます。

図0-4　出欠の答え方。絵文字はサークルごとに変更されている場合があります。
絵文字が ✅❓❌ と違うことがあります 管理者がサークル独自の絵文字に変えられるためです。意味の並び順は同じで、 左から「参加できる・分からない・できない」です。

0-4　自分がどの段かを調べる

権限は「ロール」で決まります。ロールとは、Discord で名前に付く肩書きのようなものです。 自分に何が付いているかは、メンバー一覧から自分の名前をクリックすると見られます。

図0-5　自分の段の調べ方。ロールの名前はサークルごとに違うので、迷ったら幹部か管理者に聞いてください。

0-5　「権限が足りません」と言われたら

自分の段より上のコマンドを実行すると、Bot が丁寧に断ります。 壊れたわけでも、あなたが何か間違えたわけでもありません。 このとき Bot は「誰に頼めばいいか」まで教えてくれるので、その人にお願いしてください。

図0-6　権限が足りないときの表示。表示されるロール名はサークルの設定によって変わります。
コマンドは「サーバーの中」で使ってください Bot との1対1の DM ではコマンドは使えません。どのサークルの話か Bot が判断できないためです。 通知の DM は届きますが、操作はサーバーのチャンネルから行ってください。
CHAPTER 1 — LEVEL 1

一般メンバー

部員は全員ここです。設定は要りません。まずは3つだけ覚えれば十分です。

1-1　最初に覚える3つ

図1-1　一般メンバーが最初に覚える3つ。残りは必要になったときで構いません。

1-2　桁巻きを記録する

積層作業を始めるときと終わるときに1回ずつ押します。 間の時間は Bot が数えているので、時計を見る必要はありません。 桁名はメニューから選ぶので、打ち間違いも起きません。

図1-2　桁巻き記録の流れ。押し忘れても自動で片づきますが、記録が消えるので end は忘れずに。
/layer end を押し忘れると、記録が消えます 12時間そのままだと自動で取り消され、その日の作業がまったく残りません。 作業が終わったら、片づけの前に /layer end を押す習慣をつけてください。 いま自分が記録中かどうかは /layer status で確認できます。

1-3　機体の進捗を見る

/progress view で、機体全体からパーツ・部品へとボタンで掘り下げていけます。 どこまで進んでいるかがバーで見えるので、自分の班以外の様子も分かります。

図1-3　/progress view の表示イメージ。名前や階層はサークルごとに違います。

1-4　自分の状況をまとめて見る

/me は、自分がいま抱えているものを1画面にまとめます。 週のはじめにこれを見ておくと、答え忘れが防げます。表示は自分にだけ見えます。

/me ├ まだ答えていない日程調整　　→ 押し忘れている投票が分かる ├ 今月の積層時間・層数　　　→ 自分がどれだけ巻いたか └ 担当になっている進捗ノード → 自分が受け持っている部品
タスクは /me に出ません タスクの正本は Todoist 側にあり、「どの Discord ユーザーが担当か」という情報を持っていないためです。 タスクは /task list や /task team で確認してください。

CHAPTER 2 — LEVEL 2

班長

担当は「班の日程とタスクを回すこと」と「機体の進捗を最新に保つこと」。
第1章の操作もすべて使えます。

2-1　日程調整の一生

日程調整は作ったあと、ほとんど自動で進みます。 班長がやるのは最初の /schedule create と、最後の /schedule confirm の2回だけです。

図2-1　日程調整の流れ。青が班長の操作、緑は Bot が勝手にやってくれる部分です。
/schedule create タイトル: 6月度 定例ミーティング 候補日時: 2026-07-03 19:00 ; 2026-07-04 19:00 ; 2026-07-05 13:00 ↑ セミコロン「 ; 」で区切って、いくつでも並べられます 締切: 2026-07-01 23:59
確定の登録（/schedule confirm）を忘れないでください 投票が締め切られただけでは、前日・当日のリマインドは飛びません。 日が決まったら必ず /schedule confirm まで進めてください。 間違えたときは /schedule unconfirm で取り消せます（取り消しもお知らせされます）。

2-2　機体の進捗を更新する

進捗はツリー（木）の形で管理します。機体 → パーツ → 部品…と、必要なだけ細かくできます。 /progress add で足し、/progress edit で直します。 親を指定しなければ、いちばん上（＝機体そのもの）になります。

/progress add 名前: 第2リブ　親: 主翼　担当: 翼班　進捗率: 0 /progress edit ノード: 第2リブ　進捗率: 40 /progress remove ノード: 第2リブ　← 配下ごと消えるので注意

桁巻きの記録から、進捗率を自動で計算させる

桁は /progress spar-link で「桁名」と「目標の層数」を進捗ノードに結びつけられます。 そうすると、部員が /layer end を押すだけで進捗率が勝手に上がります。 班長が手で数字を入れ直す必要はありません。

図2-2　桁巻きの記録と進捗ノードをつなぐと、進捗率が自動計算されます。
手で進捗率を入れると、自動計算が止まります /progress edit で進捗率を直接入れると、そのノードは「手入力」に切り替わります。 桁巻きから自動で更新させたいノードには、数字を手で入れないでください。

CHAPTER 3 — LEVEL 3

幹部

担当は「名簿を整えること」と「うまく動いていないときに確かめること」。
第1章・第2章の操作もすべて使えます。

3-1　通知が届く道すじをつくる

タスクを「班ごとのチャンネル」へ自動で流すには、3つをつなぐ必要があります。 どれか1つでも欠けると通知は届きません。うまく届かないときは、この図のどこが切れているかを確かめてください。

図3-1　毎朝 8:30 のタスク通知が班チャンネルへ届くまでの道すじ。

3-2　日程調整を消す・戻す

間違えて作った投票は /schedule delete で消せます。ただし 「誰が何と答えたか」は消えません。 あとから集計を見たくなったら /schedule restore で戻せます。

図3-2　削除と復元。消えるのは投票メッセージだけで、回答の記録は残ります。

3-3　名簿を整える

新入生が入ったときや班替えのときは、/member setup が便利です。 主所属・副所属・班長フラグを1回でまとめて設定できます。

/member setup 対象: @部員　主所属: 主翼班　副所属: 電装班　班長: はい /member set-leader 対象: @部員　班長: はい ← 班長フラグだけを変える /member set-channel 班: 主翼班　チャンネル: #主翼班-連絡
「班長フラグ」を付けても、班長の権限（L2）にはなりません /member set-leader で付くのは名簿の上の肩書きです。 コマンドを実行できるかどうかは、Discord のロールだけで決まります。 実際に班長として操作できるようにするには、管理者に /set_role（班長ロール）へ追加してもらってください。
図3-3　似ていますが別物です。「班長なのにコマンドが使えない」ときは右が抜けています。

3-4　うまく動かないときに確かめる

「通知が来ていない気がする」「設定がいつの間にか変わっている」というときは、 ログを見れば事実が確かめられます。どちらも表示は自分にだけ見えます。

コマンド分かること
/report notificationsBot が実際に送った通知の記録。「送られていない」のか「届いていない」のかを切り分けられます
/report changes設定や班・メンバーを誰がいつ変えたかの記録。実行者は表示名で出ます

3-5　幹部が使えるコマンド一覧

第1章・第2章のものに加えて、次が使えるようになります。

コマンド何ができるか
メンバー・班
/member setup主所属・副所属・班長フラグを一括で設定する
/member set-leader名簿の班長フラグを変える
/member set-channel班の通知先チャンネルを決める
Todoist セクションの紐付け
/task link-sectionTodoist のセクションを班につなぐ
/task unlink-sectionセクションの紐付けを外す
/task unlink-team-sectionsある班につながっているセクションをまとめて外す
日程調整・ログ
/schedule delete投票を消す（票データは残る）
/schedule restore消した投票を締切済みとして戻す
/report notificationsBot が送った通知の記録を見る
/report changes設定・マスタの変更履歴を見る
出欠の答えが悪い人を見つけたいとき /report member-attendance（班長から使えます）を実行すると、 回答率の低い順に並びます。連続で答えていない人が分かるので、声かけの目安になります。
CHAPTER 4 — LEVEL 4

Bot管理者

担当は「最初の設定」と「サークルの構成が変わったときの反映」。
すべてのコマンドが使えます。サーバーを作った人・サーバー管理権限を持つ人が自動的にここです。

4-1　導入は15分ほどで終わります

サーバーを借りたり、プログラムを触ったりする必要はありません。 Discord の中だけで完結します。

図4-1　導入の5ステップ。Todoist 連携は任意なので、あとから足せます。

4-2　/setup で決めること

質問に答えていくだけのウィザードです。あとから /set_role や /set_channel で個別に直せるので、最初から完璧でなくて構いません。

決めるもの内容
サークル名Bot の表示に使われます
班班と対応ロールをまとめて作成できます
班長ロールここに入れたロールを持つ人が第2章の操作をできるようになります
幹部ロール・管理者ロール第3章・第4章の操作をできる人を決めます
通知チャンネルタスク通知・ログの投稿先
新入生オンボーディング入ってきた人に自動で案内を出すか（既定はオフ。新歓期だけオンにするのがおすすめ）
大会日を入れておくと、逆算してくれます /settings_set key:COMPETITION_DATE value:2027-07-28 のように登録すると、 /countdown で残り日数と、節目ごとの「間に合うペースかどうか」が出ます。 遅れている節目がある週は、月曜の朝に自動で知らせます（遅れが無い週は送りません）。

4-3　Todoist をつなぐ（任意）

タスク機能を使うなら、サークルの Todoist トークンを1回だけ登録します。 トークンはコマンドの引数では受け取りません。 引数に入れた値は Discord のチャンネル履歴に残ってしまうためです。 代わりに、履歴に残らないフォーム（モーダル）で受け取ります。

図4-2　Todoist トークンの登録の流れ。やり直したいときは、同じ手順で上書きできます。
なぜフォームで受け取るのか コマンドのオプションに入れた文字は、Discord のチャンネル履歴に残ります。 トークンは Todoist のデータを読み書きできる鍵なので、履歴に残る形では受け取りません。 保存されるときも暗号化されるため、平文のまま置かれることはありません。
つながったか確かめる /todoist-status で、登録の有無・対象プロジェクト・復号できるかどうかが分かります （トークン本体は表示されません）。 やり直したいときは /todoist-setup をもう一度実行すれば上書きできます。 連携をやめるときは /todoist-remove です。

4-4　年度替わり

代替わりのときは /season rollover を実行してください。 ウィザードが順番に聞いてくれるので、手作業で名簿を直す必要はありません。

図4-3　/season rollover がやってくれること。
班長ロールの入れ替えは手作業です /season rollover がリセットするのは名簿の班長フラグだけです。 コマンドの権限は Discord のロールで決まるので、 旧班長からロールを外し、新班長へ付ける作業は別途必要です （/set_role の action:add / action:remove で1つずつ足し引きできます）。

4-5　データの持ち出しと削除

コマンド何ができるか
/data exportこのサーバーの主なデータを ZIP（CSV のまとまり）で受け取る。Excel でもスプレッドシートでも開けます
/data deleteデータの削除を申し込む。まちがい防止のためサーバー名の入力が必要。最後のバックアップが添付されます
/data delete-cancel申し込んだ削除を取り消す

※ この3つは「サーバー管理」権限があれば実行できます（Bot管理者ロールが未設定でも使えます）。

4-6　Bot管理者が使えるコマンド一覧

第1章〜第3章のものに加えて、次が使えます。設定に関するものはすべてここです。

コマンド何ができるか
初期設定・サーバー設定
/setup初期設定ウィザード。まずこれ
/set_role班長・幹部・管理者のロールを決める（action:add / remove で1つずつ増減も可）
/set_channel通知チャンネルを決める
/set_common共通設定
/settings_listいまの設定を一覧する
/settings_get / settings_set / settings_delete設定を1つずつ取得・保存・削除（大会日や保存期間など）

付録A　自動で届く通知

Bot は誰も操作していなくても、決まった時刻に通知を送ります。 「通知が多い」と感じたときは、この表のどれかを止められないか管理者に相談してください。

図A-1　1日のうちに Bot が動く時刻。予定やタスクが無い日は、何も送りません。

そのほか、いつも動いているもの

タイミング内容
5分ごと日程調整の締切判定と自動締切／締切1時間前の未回答者への催促／桁巻きの押し忘れ検知
20分ごとTodoist の取り込み・桁巻きの反映・進捗の再計算
毎週 月曜 8:30期限に遅れている節目（マイルストーン）の通知。遅れが無い週は送りません
DM が届かない人には、チャンネルで呼びかけます Discord の設定で DM を受け取らないようにしていると、Bot からの催促が届きません。 その場合はチャンネルでメンションする形に自動で切り替わります。

付録B　困ったときは

こうなったこうしてください
コマンドの一覧に何も出てこない Bot との DM で打っていませんか。コマンドはサーバーのチャンネルで使ってください（第0章 0-5）
「権限が足りません」と出た 故障ではありません。表示された依頼先のロールの人にお願いしてください（第0章 0-5）
班長なのにコマンドが使えない 名簿の班長フラグと、Discord の班長ロールは別物です。管理者に /set_role でロールへ追加してもらってください（図3-3）
/task が「管理者が登録してください」と返す そのサークルは Todoist をつないでいません。使うなら管理者が /todoist-setup を実行します（4-3）
桁名がメニューに出てこない まだ登録されていません。班長以上が /layer keta-add で追加します
班が選べない まだ班が登録されていません。管理者が /setup か /team-add で追加します
班のチャンネルにタスクが流れてこない セクション・班・チャンネルのどこかがつながっていません。/task sections で確認してください（図3-1）
手で入れた進捗率が上書きされる／されない 桁を紐付けたノードは自動計算です。手で数字を入れると手入力に切り替わり、自動更新が止まります（2-2）
日程が決まったのにリマインドが来ない /schedule confirm がまだです。確定を登録して初めて前日・当日の通知が出ます（2-1）
桁巻きの記録が残っていない /layer end を押し忘れると、12時間で自動的に取り消されます（1-2）
Bot の反応がない /ping と /health で生きているかを確認できます。動いていなければ管理者へ連絡してください
