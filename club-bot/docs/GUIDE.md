# 取扱説明書（導入するサークル向け）

鳥人間サークル 統合運営 Discord Bot を、あなたのサークルで使うための説明書です。

**この説明書を読む人**: Bot を導入するサークルの管理者・幹部・班長・部員。
サーバーを借りたりプログラムを触ったりする必要はありません。

> 運営者（Bot をホストする側）向けの手順は
> [`OPERATION.md`](OPERATION.md) と [`SETUP.md`](SETUP.md) にあります。

## 1. この Bot でできること

| やりたいこと | 使うコマンド |
|---|---|
| ミーティングの日程を決める | `/schedule create` → メンバーがリアクションで回答 |
| やることを配って追いかける | `/task add` `/task list` `/task done` |
| 桁巻きの作業を記録する | `/layer start` → `/layer end` |
| 機体の進捗を見える化する | `/progress add` `/progress view` |
| 手伝える人を探す | `/member support` |
| 今週の状況を振り返る | `/report weekly` `/report attendance-rate` |

**準備するもの**: Discord サーバーだけ。サーバー（VPS）も、Bot トークンも、
設定ファイルの編集も必要ありません。

**サークルごとに決めるもの**: サークル名・班・桁の名前・機体の構成・
通知先チャンネル。これらに初期値はなく、すべてあなたのサークルが決めます。

## 2. 導入する（管理者・約15分）

作業するのは Discord サーバーの管理者（`サーバー管理` 権限を持つ人）です。

### Step 1. Bot を招待する（1分）

運営者から受け取った招待URLを開き、自分のサークルのサーバーを選びます。

招待すると、Bot が**導入手順の案内を1つのチャンネルに投稿します**
（`#bot-log` があればそこ、無ければサーバーの「システムメッセージチャンネル」、
それも無ければ Bot が書き込める最初のチャンネル）。案内には
`/setup` `/setup-status` `/help` の3つが書かれています。

Bot に `ロールの管理` と `チャンネルの管理` が付いている場合は、あわせて次も作られます。

- `幹部` ロールと `Bot管理者` ロール
- `#bot-log` チャンネル（Bot の動作ログが流れます）

> **標準の招待URLはこの2つの権限を要求しません**（必要最小限の権限しか
> 求めない方針のため）。ロールとチャンネルが作られなかった場合は、
> 次のどちらかで設定してください。
> - **自分で作成し、Step 2 の `/setup` で指定する**（すぐ反映されます）
> - Bot に `ロールの管理` と `チャンネルの管理` を付ける
>   （同じ名前のロール・チャンネルが無ければ、Bot の次回起動時に作成されます）
>
> どちらでも Bot 自体は動きます。

> **コマンドが出てこないとき**は少し待ってください。Discord への反映に
> 最大1時間ほどかかることがあります。急ぐときは Ctrl+R で Discord を再読み込みします。

### Step 2. `/setup` で基本設定（5分）

`/setup` と入力すると、設定ウィザードが開きます（自分にだけ見えます）。

1. **通知チャンネル**をセレクトメニューから選ぶ
   - お知らせ先 / タスク通知先 / Bot ログ
2. **ロール**を選ぶ（幹部・Bot管理者）
3. **「サークル名を設定」ボタン** → サークル名を入力
   （週次サマリーなどの表示に使われます）
4. **「班を一括作成」ボタン** → 班名をカンマ区切りで入力
   例: `主翼班, 尾翼班, 電装班, フェアリング班`
   班と、対応する Discord ロールがまとめて作られます

### Step 3. 班を整える（3分）

一括作成で足りない場合や、後から変えたい場合に使います。

```
/team-add slug:wing name:主翼班       ← 班を追加（slug は半角英小文字の識別子）
/team-list                            ← 一覧（有効/無効・人数・ロール）
/team-role team:wing role:@主翼班     ← 既存の Discord ロールと紐付け
/team-remove slug:wing                ← 無効化（人がいる場合は confirm:True が必要）
```

技能タグ（「溶接できる」「CAD できる」など）も登録できます。

```
/skill-add name:CAD
/skill-list
```

### Step 4. メンバーを登録する（5分）

```
/member register user:@山田 team:主翼班       ← 1人ずつ
/member setup user:@山田 primary_team:wing secondary_teams:cfrp is_leader:True
                                              ← 主所属・副所属・班長をまとめて設定（幹部以上）
```

**班長には班長ロールを設定してください。** Bot が班長として扱うのは、
ここで登録したロールを持つ人です（班長向けのコマンドがすべてこれを見ています）。

いちばん簡単なのは `/setup` です。「設定したい項目」で **班長ロール** を選び、
下のロールセレクトで班長ロールを選びます（複数選択できます）。

```
/setup    ← 「班長ロール」を選んでロールを選択（選び直すと置き換わります）
```

1つだけ足す・外すときは `/set_role` を使います。

```
/set_role role_type:リーダー role_id:<班長ロールのID>                 ← 追加
/set_role role_type:リーダー role_id:<班長ロールのID> action:削除     ← 1つだけ外す
```

> ロールIDは、Discord の設定で開発者モードを ON にしてから
> ロールを右クリック →「ロールIDをコピー」で取得できます。
> 複数まとめて追加する場合はカンマ区切りで指定します。
> `.env` に `LEADER_ROLE_IDS` を書いて運用している場合は `.env` が優先されます
> （その場合はコマンドの結果にその旨が表示されます）。

### Step 4.5. 新入生オンボーディング（任意・新歓期向け）

新歓で一度に何十人も入るサーバー向けの機能です。**既定は OFF** で、
ONにしない限り参加者には何も送りません。

`/setup` の「新入生オンボーディング ON/OFF」ボタンで切り替えます。ONにすると、
参加した人へ DM で「班を選ぶ」ボタンが届き、押して班を選ぶと名簿に登録され、
班のロールが付きます（幹部が `/member register` を1人ずつ打つ必要がなくなります）。

- **DM を受け取らない設定の人**のために、`/setup` の「新入生の案内チャンネル」を
  設定してください。未設定だとその人には案内が届きません
  （読めないチャンネルへ勝手に投稿することはしません）
- **班ロールの自動付与には2つの前提があります**: Bot に「ロールの管理」権限があること、
  そして班にロールが紐付いていること（`/team-role`）。どちらが欠けていても
  名簿への登録は行われ、ロールが付かなかったことが本人に伝わります
- 参加しただけでは名簿に登録されません（見学者や再参加の方が混ざらないようにするため）

### Step 5. 動くか確かめる（1分）

```
/ping      ← 応答が返れば OK
/health    ← DB・Todoist・暗号鍵の状態を表示
```

これで導入は完了です。

## 3. 役割別・最初に覚えること

### 部員（全員）

この3つだけ覚えれば使えます。

| したいこと | コマンド |
|---|---|
| 出欠に答える | コマンド不要。投票メッセージに ✅ / ❓ / ❌ を押す |
| 自分のタスクを見る | `/task list mine:True` |
| 桁巻きを記録する | 始めるとき `/layer start`、終わったら `/layer end` |

### 班長

上に加えて、班のタスクと日程を回します。

```
/schedule create ...        日程調整をつくる
/task add ... team:主翼班    班のタスクを登録
/task team 主翼班            班のタスク一覧
/report weekly              今週のサマリー
/progress add / edit        機体の進捗を更新
```

### 幹部

```
/member setup               所属班・班長をまとめて設定
/report audit               直近の操作履歴
/schedule delete            日程調整の削除（票データは残ります）
/schedule restore           削除した日程調整を戻す
```

`/schedule delete` は投票メッセージを消して締切扱いにしますが、**誰が何と答えたかは残します**。
消してから「やっぱり集計を見たい」となったら `/schedule restore` で戻せます
（投票メッセージは戻らないので、取り直すときは `/schedule create` で作り直してください）。

### 管理者

```
/setup                      設定ウィザード
/team-add /skill-add        班・技能タグの管理
/set_channel /set_role      通知先・ロールの変更
/todoist-setup              Todoist 連携（任意）
```

## 4. 場面別の使い方

### 4.1 ミーティングの日程を決める

**つくる**（班長以上）

```
/schedule create
  title:      定例ミーティング
  options:    2026-07-03 19:00; 2026-07-04 19:00; 2026-07-05 13:00
  deadline:   2026-07-02 23:59
  place:      部室（任意）
  target_role: @主翼班（任意・特定の班だけに聞くとき）
```

候補は **`;`（セミコロン）区切り**で並べます。

**決まった日程を登録する**（班長以上）

締切後の集計だけでは「結局いつに決まったのか」が残りません。`/schedule confirm` で
確定した候補を登録すると、対象ロールへ告知し、`/schedule list` `/schedule list-closed` に
確定日が表示され、**前日 20:00 と当日 08:30 にリマインド**が届きます。

```
/schedule confirm    schedule_id:（候補から選ぶ） option_id:（候補から選ぶ）
/schedule unconfirm  schedule_id:（候補から選ぶ）   ← 取り消し（取り消しも告知されます）
```

`target_role` を **省略すると、名簿の現役メンバー全員**が締切前の催促の対象になります。
班だけに聞くときは必ず指定してください。

**答える**（全員）

候補日ごとに投稿されるメッセージに、リアクションで答えます。

| 絵文字 | 意味 |
|---|---|
| ✅ | 参加 |
| ❓ | 未定 |
| ❌ | 不参加 |

1つの候補につき1つだけ選べます。押し直せば前の回答は自動で外れます。

**見る・締める**

```
/schedule list              開催中の一覧
/schedule status <id>       結果の詳細
/schedule remind <id>       未回答者へ催促（班長以上）
/schedule close <id>        手動で締切（班長以上）
/schedule edit-deadline     締切の変更
```

締切は自動でも処理されます（5章）。

> **絵文字を変えたい**: `/schedule emoji set` でサークルのカスタム絵文字に
> 変更できます（管理者）。変更は**その後に作る日程調整**から適用されます。

### 4.2 タスクを配って追いかける

```
/task add title:リブ切り出し due:2026-07-05 18:00 assignee:@山田 team:主翼班 priority:2
/task list                  一覧
/task list mine:True        自分の担当だけ
/task team 主翼班            班のタスク
/task done <id>             完了
/task assign <id> @佐藤      担当者変更（班長以上）
/task overdue               期限切れ一覧
```

優先度は 1〜4（数字が大きいほど高い）。

**「今日やること」**をマークしておくと、毎朝まとめて通知されます。

```
/today task リブ切り出し
```

### 4.3 桁巻きの作業を記録する

まず桁名を登録します（班長以上・最初の1回だけ）。

```
/layer keta-add name:主桁1
/layer keta-add name:主桁2
/layer keta-list
```

以降は作業のたびに2コマンドだけです。

```
/layer start keta:主桁1 layer_num:5     ← 始めるとき（桁名は候補から選べます）
/layer end                              ← 終わったとき（作業時間が自動計算されます）
/layer status                           ← 今、誰が何を巻いているか
```

- 層番号は数字のほか「シュリンク」などの文字でも構いません
- 同じ人が二重に開始することはできません
- 記録は `/progress` の進捗にも反映できます（次項）

### 4.4 機体の進捗を見える化する

**組み立てる**（班長以上）

```
/progress add name:1号機                      ← 親を指定しないと「機体」（最上位）
/progress add name:主翼 parent:1号機
/progress add name:主桁 parent:主翼
```

`parent` はツリーが字下げ表示される候補から選べるので、IDを覚える必要はありません。

**進捗を入れる**

```
/progress edit node:主桁 progress:50%   ← 0.5 でも 50% でも可
/progress edit node:主桁 assignee:山田 status:製作中
```

**桁巻きの記録を自動反映させる**

```
/progress spar-link keta:主桁1 node:主桁 target_layers:20
```

こうしておくと、`/layer end` で積層を記録するたびに
「完了層数 ÷ 目標層数」が主桁の進捗率へ自動で入ります。

**見る**（全員）

```
/progress view
```

機体 → パーツ → 部品とボタンで降りていけます。各階層に進捗バーが出ます。
親の進捗率は、子の平均から自動で計算されます（手で入れる必要はありません）。

```
削除: /progress remove node:主翼    ← 配下ごと消えます
```

### 4.5 班をまたいで手伝える人を探す

```
/member skill add skill:CAD              自分の技能タグを登録
/member support team:主翼班 skill:CAD    条件に合う人を検索（班長以上）
/member profile user:@山田               所属・技能の確認
```

### 4.6 振り返る

```
/report weekly              今週のサマリー（班長以上）
/report attendance-rate     出欠率の一覧（班長以上）
/report export-tasks        タスク一覧を CSV で出力（班長以上）
/report audit               直近の操作履歴（幹部以上）
```

### 4.7 Todoist と連携する（任意）

すでに Todoist を使っているサークル向けの機能です。使わなくても他の機能は動きます。

1. 管理者が `/todoist-setup` を実行し、表示されるフォームに
   サークルの Todoist API トークンを入力します
   （**コマンドの引数ではなくフォームに入力**します。履歴に残りません。
   トークンは暗号化して保存され、運営者に渡す必要もありません）
2. 班長（またはサーバー管理権限を持つ人）が `/progress setup` を実行し、
   Todoist プロジェクト → 進捗ツリーのノード → 通知先チャンネル を選びます
3. 以降 20 分ごとに自動で同期されます
   - Todoist のタスク・サブタスクが進捗ツリーに取り込まれます
   - Todoist で完了にすると、進捗が 100%・状態「完了」になります

```
/todoist-status     連携状態の確認（トークン自体は表示されません）
/todoist-remove     連携の削除
/progress sync      今すぐ同期（管理者）
```

### 4.8 Web ダッシュボードで表を見る・CSV に出す

運営者がダッシュボードを公開している場合、ブラウザから
**Discord でログイン**して、自分のサーバーのデータを表で確認できます。

- 見られる表: タスク / メンバー / 班 / 日程調整 / 出欠回答 / 桁巻き積層記録 / 機体進捗
- **出欠回答は予定ごと、桁巻き記録は桁ごとのタブ**で切り替えられます
  （スプレッドシートのシートのように表の下にタブが並びます。
  多いときは横スクロール）
- 出欠回答は**候補日時ごとの行**に「参加 / 不参加 / 未定 / 未回答」の
  メンバー名と人数が並ぶ表で表示されます
- 人物・チャンネルは ID ではなく**サーバーでの表示名・チャンネル名**で、
  日時は**日本時間（秒まで）**で表示されます
- **班長以上**は表のセルをクリックして直接編集できます（変更は履歴に残ります）
- どの表も **CSV でダウンロード**できます（Excel でもそのまま開けます）
- 機体進捗は横棒グラフでも表示されます

**表示・編集できるのは自分のサーバーのデータだけ**です。他大学のサークルの
データが見えることはありません。

## 5. 自動で届く通知

設定しなくても、次の通知が自動で届きます。

| いつ | 何が |
|---|---|
| 締切1時間前 | 日程調整の未回答者へ DM（DM が届かない人にはチャンネルでメンション）。対象は `target_role` を指定していればそのロール、していなければ**名簿の現役メンバー** |
| 5分ごと | 締切を過ぎた日程調整を自動で締め切り、結果を投稿 |
| 5分ごと | `/layer end` の押し忘れ検知。4時間経過で本人へ DM、12時間経過で自動取り消し（記録は残しません）|
| 前日 20:00 | `/schedule confirm` で確定した日程の前日通知（「明日 …」） |
| 当日 08:30 | 同じく当日通知（「本日 2026/10/01 18:00 **合宿**（部室）」） |
| 毎朝 08:30 | 今日〜7日以内が期限の未完了タスク |
| 毎朝 08:30 | 「今日やること」ラベルの付いたタスク |
| 毎朝 08:30 | Todoist のセクション別タスク（期限7日以内・超過）を班チャンネル（未設定ならタスク通知チャンネル）へ（連携している場合） |
| 毎朝 08:30 | Todoist 連携プロジェクトの期限タスク（連携している場合） |
| 毎週月曜 08:30 | **遅れている**マイルストーンのお知らせ（遅れが無い週は送りません） |
| 20分ごと | 機体進捗の同期・再集計（Todoist と桁巻きの反映） |
| 毎日 21:00 | 期限切れの未完了タスク |
| 毎日 04:00 | `/data delete` を申告したサーバーのデータ削除を実行し、結果を `#bot-log` へ（退出済みサーバーは通知先が無いため送られません） |

送信先は `/setup` や `/set_channel` で設定したチャンネルです。

## 6. 権限のしくみ

コマンドは4段階の権限で分かれています。上の権限は下をすべて含みます。

| レベル | 誰が | Bot での判定 |
|---|---|---|
| L1 一般部員 | 全員 | 既定 |
| L2 班長 | 班長 | `/set_role role_type:リーダー` で登録したロールを持つ |
| L3 幹部 | 幹部 | `幹部` ロール（`/set_role role_type:実行役`）を持つ |
| L4 管理者 | 管理者 | `Bot管理者` ロール、サーバー管理者権限、またはサーバーのオーナー |

権限が足りないコマンドを実行すると、その旨のメッセージが自分にだけ表示されます
（他の人には見えません）。

## 7. 困ったときは

| 症状 | 対処 |
|---|---|
| コマンドが候補に出てこない | 招待直後は反映に最大1時間かかります。Ctrl+R で再読み込みも試してください |
| `/setup` が「権限がありません」 | サーバー管理者権限か `Bot管理者` ロールが必要です |
| 班の候補が出てこない | 先に `/team-add` か `/setup` の「班を一括作成」で班を登録してください |
| 班長なのに班長向けコマンドが使えない | `/setup` の「班長ロール」で班長ロールを登録したか確認してください |
| 投票のリアクションが反映されない | Bot に「リアクションを追加」「メッセージ履歴を読む」権限があるか確認してください |
| 催促の DM が届かない | 受け取る側の DM 設定です。届かない場合はチャンネルでのメンションに自動で切り替わります |
| `/layer end` で「進行中のセッションがありません」 | 先に `/layer start` を実行してください。誰かの記録を代わりに終わらせることはできません |
| 桁名を間違えて開始した | `/layer cancel` で記録を残さず取り消し、正しい桁名で `/layer start` し直してください |
| `/layer end` を押し忘れて帰った | 4時間で DM が届きます。12時間で自動的に取り消され、記録は残りません（分数は `/settings_set` で変更可） |
| `/progress view` に何も出ない | まだ機体が未登録です。`/progress add name:1号機` から始めてください |
| Todoist が「未登録」 | 管理者が `/todoist-setup` を実行してください |
| 通知が来ない | `/setup` で通知チャンネルを設定したか、Bot がそのチャンネルに書き込めるか確認してください |

`#bot-log` チャンネルには Bot の動作ログとエラーが流れます。
うまくいかないときは、まずここを見てください。

## 8. 年度替わりの引き継ぎ

代替わりのときにやることです。**`/season rollover` が中心**になります。

### まず `/season rollover` を実行する

`/season rollover name:2027年度` を実行すると、ウィザードが開きます
（年度名は自由です。`第31代` のような呼び方でも構いません）。

1. 卒業する人をメニューから選ぶ（選ばなければ全員が継続）
2. 「確定する」を押す

これで次のことが一度に行われます。

- 現在の年度を終了し、新しい年度を開始する
- 選んだ人を **卒業（alumni）** に切り替える
- **班長フラグを全員リセット**する（新体制で付け直すため）
- 切り替え時点の主要7テーブルを **年度スナップショット**（ZIP）として添付する

**卒業者のデータは削除されません。** 過去の作業記録に残る担当者名を
引けるようにするためです。卒業した人は `/member support` などの
既定の検索から外れ、必要なときは `include_alumni:True` で含められます。

添付される ZIP は `/data export` と同じ内容です。引き継ぎ用に保存してください。

### そのあとにやること

1. **管理者の引き継ぎ**: 新しい代表に `Bot管理者` ロールを付ける
2. **班長の設定**: `/member setup user:@新班長 is_leader:True` で新しい班長を設定
   （`/season rollover` で全員のフラグが外れています）
3. **班の見直し**: 班が変わるなら `/team-add` `/team-remove`
4. **機体の切り替え**: 新機体を `/progress add name:2号機` で追加します。
   旧機体の記録を残したい場合はそのままにしておけます
   （消す場合は `/progress remove` で配下ごと削除）
5. **大会日の更新**: `/settings_set` で `COMPETITION_DATE` を新しい大会日に変え、
   `/milestone add` で今年の節目を登録し直します
6. **桁名の整理**: `/layer keta-remove` で使わない桁名を無効化
   （記録自体は残ります）
7. **Todoist**: アカウントが変わるなら `/todoist-remove` → `/todoist-setup` で再登録

年度の一覧は `/season list` で確認できます。仕分けをせずに年度だけ
切り替えたい場合は `/season new name:<名前>` を使います。

## 9. データの扱いと利用をやめるとき

**保存されるもの**: Discord のユーザーID・表示名・所属班・技能タグ・
出欠回答・タスク・桁巻きの作業記録・機体進捗・操作履歴。

**保存されないもの**: メッセージの本文、DM の内容。
この Bot はメッセージを読み取る権限（MESSAGE CONTENT）を要求していません。

**他のサークルとの関係**: すべてのデータはサーバー単位で完全に分離されています。
他大学のサークルからあなたのデータが見えることはありません。

**持ち出し**: `/data export` でこのサーバーの主要7テーブルを ZIP（CSV 群）として
受け取れます（管理者のみ）。サーバーIDや Todoist トークンは含まれません。

**利用をやめるとき**: 運営者への連絡は不要です。Bot をサーバーから
キックすれば動作が止まり、**30日後にデータは自動削除されます**
（誤操作に備えた猶予期間です。その間に再招待すればデータは戻ります）。
すぐに消したい場合は `/data delete` を実行してください
（確認のためサーバー名の入力が必要です）。`/data delete-cancel` で
取り消せます。詳しくは [プライバシーポリシー](PRIVACY.md) の「保存期間」を
参照してください。

詳しくは [利用規約](TERMS.md) と [プライバシーポリシー](PRIVACY.md) を参照してください。
